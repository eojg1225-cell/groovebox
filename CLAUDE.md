# GrooveAccess (repo: groovebox)

Web-first groovebox (techno, DnB, dub, jungle). Full spec: `groovebox-brief.md` (read it first).

## Rules
- Work milestone by milestone (section 12 of the brief); keep the build green; commit after each working step.
- `src/engine`, `src/instruments`, `src/fx` must stay free of DOM and Web Audio code.
- Audio thread: no allocation per block, no console.log, no blocking.
- Keep sound design basic at first; clean interfaces for refining later.
- Must work in desktop Chrome/Edge and Silk on a Fire tablet (touch, multi-touch).
- `main` is the source of truth: every session starts from it. After committing a working step, push it to the session branch and also to `main` (`git push origin HEAD:main`; if `main` moved, merge `origin/main` first, never force-push), so the next session starts with every change.

## Platform plan (agreed; not started)
Goal: the Android / Fire APK becomes the main version; the web build stays as the dev and preview build. Order:
1. **Sound first.** Finish the sound design in the TypeScript engine (current milestones). No port while the sound still changes: every tweak would have to be made twice.
2. **Capacitor shell (can come earlier).** Wrap `dist/` in a Capacitor Android app (served from `https://localhost` so AudioWorklet works; media playback without a gesture, keep screen on, immersive, landscape); a native `ProjectStore` (Capacitor Filesystem / Preferences) instead of localStorage; sideload on the Fire or publish to the Amazon Appstore (no Google Play Services). Measure the Fire with OboeTester (round-trip latency, MMAP support) to see what a native engine would gain.
3. **Native engine.** Port `src/engine`, `src/instruments`, `src/fx` to Rust (a thin C++ Oboe shim for the audio callback: AAudio, LowLatency + Exclusive, buffer = 1-2 bursts, sustained performance mode), behind the existing message protocol, so the UI barely changes. Keep `double` for filter / oscillator state, the same random generators, flush denormals to zero. Port module by module and **null-test** each against the TypeScript engine (render the same project offline, subtract, expect around -100 dB or lower).
4. **After the port:** the APK is the product (releases, latency work, Android-only features behind small interfaces like `ProjectStore`). The same Rust engine compiles to WASM for the web build (same UI, same sound): used for development, tests and the Artifact preview, never maintained or tuned separately. Then update this file's targets to "Android / Fire APK first; web = dev and preview build".

## Keeping these docs right
- This file describes the app **as it is now**. When behaviour changes, edit the section it belongs to (replace the old description, don't append a dated note), and add a one-line entry to `docs/HISTORY.md`.
- Save format changes: bump `PROJECT_VERSION` (`engine/project.ts`), add the load migration in `engine/projectFile.ts` (named after the version it upgrades from, e.g. `...V40`, guarded by the stored `version`), and record it in `docs/HISTORY.md`. Old migrations can be retired by raising `OLDEST_EXACT` (as in October 2026, see HISTORY).
- `ARCHITECTURE.md` = code structure, message protocol, data model. Keep its protocol table in step with `engine/protocol.ts`.
- Never trust a comment over the code: if they disagree, fix the comment in the same commit.

The grid: rows of bars + pattern A-D / OFF per track, switched at bar lines, looping. Knobs: top = each track's pattern in the cursor row, bottom 1 = BARS. Armed tracks (`songArmed`): the cursor's track, plus those armed with a channel tap (tap again = disarmed; not saved, `App.songTracks`); each has a yellow cursor frame in the cursor row and its channel button lit; the pattern letters stay teal. A-D = that pattern on the armed tracks in the cursor row (the others keep theirs; OFF via a cell's knob or CLEAR; `App.songPattern`). CLEAR / COPY (`songHold`, `songBox`): held, ◀ ▶, ROW ▼ / ▲ and strip keys (a drag; the first key starts the box) grow a box from the cursor over the armed tracks; while held, every cell the release would change is shaded and shows in yellow what it would read after (CLEAR: -, a COPY box: as it is, a COPY tap with something copied: the paste; `songPending`); release = CLEAR sets its cells OFF (rows stay) / COPY copies them, OFF cells and each row's bars too (`songClip`); a tap = the cursors' own cells; a COPY tap with something copied pastes it with its first row on the cursor row (the first track on the cursor's; whole rows or the cursor on BARS: on their own tracks, with their bars), rows past the end added (`songPaste`); the copy stays for more pastes until another COPY box or a mode change. ### Patterns and steps
- 8 tracks x 4 patterns A-D, 1-64 steps (STEPS held + ◀ / ▶ = a step shorter / longer). BAR tap = next bar on the strip, BAR + ◀ / ▶ = previous / next; BAR + ▶ on the last bar adds an empty one (up to 4; BAR works on a one-bar pattern too). While playing, PLAY, DESIGN and live recording (placing RING / SLIDE / ACCENT / GHOST included) follow the playhead (`App.followsPlayhead`; BAR is off there).
- PLAY starts from the bar the strip shows for the selected track (BAR picks it, stopped, in every mode): every track starts where it would be had all played from the top until then (`Engine.startAt`; a 2-bar HAT from bar 4 plays its bar 2; notes started earlier don't sound). STOP keeps each track's bar (`App.keepBars`), so PLAY carries on from there. FUNC + PLAY = from the top (stopping: back to the top for the next PLAY) and lets go of FUNC (held or latched).
- A-D = every track's pattern; hold channels + A-D (several at once): HOLD + PATTERN KEEP HELD (default) = every track but those switches, SWITCH HELD = only those; FUNC does nothing to A-D. Playing, a switch always waits for the track's loop end (any mode); stopped = at once.
- Speed per pattern: normal / double / half / triplet (the TIME key cycles them, its label shows the speed; screen X2 / /2 / T). One master 16th clock; `Engine.stepChannel` runs each track's own steps.
- TIME SIG (`project.meter`, `METERS`): each 16-step bar has four groups and plays the first n of each; dark steps take no time (the strip shows them ×, unless STEPS switched them back on); changes at the next bar line. STEPS tap = STEPS mode: strip taps flip a step on / off (`Step.flip`).
- Step flags: SLIDE (303-style: held through to the next note and glides into it; legato playing on BASS / LEAD slides too), RING (held until the next hit or REST; drums ring with long decay), ACCENT / GHOST (velocity 1 / 0.45, normal 0.8; ACC/GHOST per track scales the distance), REST (always cuts everything sounding on the track: held, tied, ringing and releasing notes, drum decays, PAD notes of their own lengths, over a 3 ms fade, `Instrument.cut`, `CUT_FADE`, `Engine.cutTrack`; onboard delay / room and FX tails ring on; a muted track's notes play out), locks (`Step.locks`: any knob, automation.ts keys, the track's own sound params by bare id; set in STEP EDIT, sound params also by live recording; they glide from lock to lock as the pattern plays, hold after the last until the loop starts again, the knob as set before the first; a SONG lock on the same knob wins; `Engine.runPatAuto`; while playing, a knob showing on the panel / screen follows its locks at the playhead, SONG lanes included (`App.heardTarget`, display only; a knob turned in the last second shows its own value)), PAD / PLUCK chord notes (`Step.extra`, each with its own length `Step.extraGate`; the engine holds their notes each by its own length, `holdStart` / `stepHolds`, so a later note no longer cuts an earlier one; RING / SLIDE steps keep the one-note gate; a CHORD other than OFF plays only the step's lowest note, as its root; a SLIDE glides the chord voice by voice: root to root, 3rd to 3rd ..., at the sound's SLIDE time).
- Drum ROLL (the SLIDE flag on drums): consecutive ROLL steps roll as one run at the sound's ROLL RATE, a note value at the tempo whatever the pattern's speed (1/4, 1/8., 1/8, 1/16 (default), 1/32, 1/32T, 1/64; `ROLL_DIVS` hits per 16th; straight through swing): a run plays the hits that start inside it (a 4-step run at 1/8: 2; at TIME X2 a 1/16 run hits every other step), velocity ramping from the first step's dynamic to the last's; lone ROLL steps don't roll.
- TRIM (per synth track): the last step of a sequenced note is held this long (0.125-2 steps). Drums play out their own decay; their slot holds RING instead (per track, x0.25-x4, x1 = as designed: how long RING steps ring, `Drum.setRingLength`). The slot follows the track's type (TRACKS). The SAMPLER, when it comes, takes TRIM.
- CLEAR held + step = clear it; + channel = clear that track's pattern; + A-D = clear that pattern of the selected track (the current one too). COPY held + channel = this pattern's notes to the same slot on that track (any type; the target keeps its own sound: a chord onto a one-note track keeps its lowest note, a drum's hits onto a pitched track its base note, onto a drum its own pitch; locks only between the same type); + A-D = to that pattern of this track. COPY BAR (RECORD / PLAY): COPY held + BAR = copy the bar the strip shows; ◀ ▶ pick the target bar (the strip shows it as steps on any track and stops following the playhead; ▶ past the end grows the pattern by an empty bar, up to 4; ◀ back takes it away again), COPY = paste all 16 steps over it (empty and STEPS-off ones too; the pattern grows to cover it), CANCEL = nothing copied (`App.copyBar`, `pasteBar`).
- Each pattern has its own patch (`Pattern.patch`; the pattern being edited keeps its patch in the channel's `sounds` / `trims` / `presets`: always use `patchOf` / `setPatchOf` / `editPattern`).

### Sounds
- Track types: 1 KICK, 2 SNARE, 3 HAT, 4 PERC (pitched toms / percussion), 5 BASS, 6 PAD, 7 LEAD, 8 PLUCK (default layout; any track can take any type).
- **Layers**, bottom to top: TIMBRE / INTENSITY macros (`macros.ts`: TIMBRE blends five designed sounds per type; INTENSITY = modulation amount, below 50 % towards a dull floor, above excited (synths: below 50 % the filter also follows the note above the type's home note, 75 % at INT 0 (`Synth KEY_TRACK`, `keyref` = BASS 33, else 45), so a dull sound stays within about 4 dB of its INT 50 up to A5 instead of fading out on high notes; bit-identical from INT 50 up); the KICK's sounds instead each have their own INT 0 (soft, slow thump) and INT 100 (extreme) versions, `Anchor.soft` / `hard`; PERC COWBELL has its own soft end so INT 0 keeps its metal) < SOUND page knobs (stored as **trims** on top of the macros, `trims.ts`, so turning TIMBRE keeps them) < LIVE knobs (relative, in the engine via `setOffset`).
- Five TIMBRE sounds per type: KICK 808 BOOM / VINTAGE / PUNCH / TECHNO / PSY DOOF; SNARE RIMSHOT / PICCOLO / TIGHT / BREAK / INDUSTRIAL; HAT RIDE / HAT / SPLASH / CRASH / CHINA; PERC LOW TOM / CONGA / COWBELL / TIMBALE / CLAVE (skins, metal, wood); BASS SINE SUB / GROWL / ACID / SOLID / FM 2:3; PAD WARM / STRINGS / TINE / GLASS / ETHEREAL; LEAD WHISTLE / SQUARE / SUPERSAW / HOOVER / FM BITE; PLUCK STEEL / GLASS PLUCK / SAW PLUCK / SQUARE PLUCK / RAGE DONK.
- Loudness: every TIMBRE sound on every type plays equally loud at the default VOLUME, at INT 0, 50 and 100 (within 1 dB; tests; measured 0.43 dB apart). The measure is GATED (`tools/lab/loudness.ts` `gatedLoudness`): one hit / a half-second note, K-weighted, averaged over the samples whose 10 ms loudness is within 20 dB of the loudest moment, so short sounds (a hat passes the gate for ~30 ms) and long ones are compared on how loud they are while they sound, not diluted by their tail. Per-sound `ogain` evens a type's sounds (its `soft` / `hard` ogain evens INT 0 / 100; an end with only `ogain` changes nothing else); `InstrumentEntry.gain` sets the type, all against the KICK.
- SOUND page layouts live in `registry.ts` (`drumPage`, `synthPage`, FUNC layers) — read them there, not here. Synths follow the sound chain: 1 TIMBRE / INT, 2 amp envelope, 3 FM ATK / FM DEC, 4 FM LVL / RESO, 5 FLT ATK / FLT DEC, 6 FLT ENV / CUTOFF, 7 DRIVE / CRUSH (PAD: DRIVE / UNISON, no CRUSH), 8 BASS SLIDE / SUB, PAD CHORD / SLIDE (DETUNE on its FUNC), LEAD SLIDE / DETUNE (FUNC: VIBRATO / VIB RATE on 3, BEND / BEND TIME on 7, VIB DELAY / UNISON on 8), PLUCK DLY TIME / DLY FDBK. Every FUNC layer also holds PRESET (module 1 top), MID FREQ (4 bottom), LIVE 1 / 2 (5), LIVE 3 / 4 (6). Drums have no other FUNC knobs, except KICK / SNARE: SWEEP / SWP TIME on FUNC 2. KICK page: 5 CLK RESO / CLK NOISE, 6 AIR LVL / AIR SIZE; SNARE: 5 MTL TONE / MTL NOISE, 6 AIR LVL / AIR SIZE; 8 ROLL RATE / BALANCE on every drum.
- PAD: module 2's ATTACK / RELEASE and FUNC DECAY / SUSTAIN move both oscillators, and FM LVL moves FM LVL2 too (`registry.linkedParams`, applied in `App.paramTarget`, in live knobs via `liveTargets`, on load for saves without them); OSC 2's own ATTACK / RELEASE are FUNC module 3, FM LVL2 (stack 2's modulation) FUNC module 4 top. SLIDE (time): PAD module 8 bottom, PLUCK FUNC module 3 top.
- Live knobs: two per track (+ two with FUNC), defaults in `INSTRUMENTS[kind].live` / `liveFunc` (KICK / SNARE / HAT top knob = FX1:MOD / FX1:DELAY / FX1:FILTER; PLUCK LIVE 1-4 = CUTOFF / SPACE (its DLY MIX + VERB) / SUSTAIN / NOTES); macros in `LIVE_MACROS`. LIVE 1-4 can take the type's macros, every knob on its SOUND page (both layers), the mixer, every FX effect's VOLUME and FX 1's FILTER (`FX_LIVE`, ids `fx<n>:<param>`, named `FX<n>:...`; they move the bus knob itself) and the LFO. Relative: centred = the sound as set, ±60 % of the range with a taper; CUTOFF / RESO / CHORD / NOTES, choice knobs (ROLL RATE, DLY TIME), mixer, FX and LFO ids are absolute. RESET centres them.
- **Drums** (`Drum.ts`): layers body (tone + sweep), click, metal (808-style bank / ring-mod / FM + noise; HAT only: BELL `m_bell`, eight sine partials at a cymbal bell's ratios past the metal's high-pass, and RATTLE `h_rattle`, four jingle re-hits gating the metal's start; TIMBRE's (only RIDE has them: a high ride, about 1.47 kHz, after the Boss DR-3's ride bell; INT leaves its pitch), no knob) -> DRIVE -> CRUSH (fractional-rate) -> OUT GAIN -> AIR (KICK, SNARE: the small mono room heard on sampled breaks, `instruments/airRoom.ts`, run in `Drum.post`: the drum through a fixed pre-EQ per type (`DrumVoice.air`: KICK high-pass 300 Hz x2 / low-pass 1.4 kHz, no treble; SNARE 600 Hz x2 / 5 kHz, never muddy), then early reflections and a short tail of damped combs + two allpasses, added mono to both sides; AIR LVL (square law, 0 = off and idle; range as with the old stereo room: KICK as loud early on, SNARE 3 dB under) / AIR SIZE (only the tail's RT60, 0.03 s to 1.2 s exponential, default 0.4 = 0.13 s; the delays stay put, so turning it never clicks)). No filter per drum (FX 1's FILTER is the kit's). BALANCE between the elements; RING = (decays x3 + a fixed 0.6 s extension) x the track's RING. A retrigger fades the old hit over 3 ms.
- **Synths** (`Synth.ts`, up to 6 voices): BASS mono (one envelope for both oscillators, own filter envelope, sub, FM ratio ladder 1:2 / 2:3 / 3:2 root-locked, a squelch above FM LVL 60 (`Synth.squelch`: the FM pair's depth curves up to 8x at the top, index 40 on the strike / 4 settled, was 5 / 0.5; every TIMBRE sound at 60 or under plays as before), SIDECHAIN DUCK from KICK hits, FUNC under module 7); PAD polyphonic, algorithm 2 (two FM stacks, stack 2 mixed in by CARRIERS (no knob: 0.85 on every TIMBRE sound, INTENSITY fades it out below the middle and up to 1 in the top quarter; INTENSITY leaves FM LVL / FEEDBACK alone); chords via CHORD / NOTES or on-step notes; between two TIMBRE sounds its modulator ratios take a detour (`macros.RATIO_ARC`: FM RATIO up an octave and back, RATIO 3 up then down twice as fast, snapped to whole / half steps), so the timbre keeps changing all the way, about 87 ratio stops across the knob); LEAD mono on the BASS / PLUCK engine (algorithm 0: SHAPE's waves into an FM pair, OSC 2 detuned, UNISON, one envelope; a new note takes over as on the BASS) plus delayed VIBRATO (`vibrato` semitones, `vibrate`, `vibdelay`: swells in over the delay) and a pitch envelope (`bend` semitones, `bendtime`: each note bends into its pitch), per note (`Synth.notePitch`, ramped per block); INTENSITY opens filter / envelope / DRIVE / DETUNE and leaves FM, vibrato and bend alone; PLUCK polyphonic with onboard delay + room (CHORD / DETUNE and DLY MIX / VERB on FUNC). Every synth has an FM envelope of its own (FM ATK / FM DEC, `fmattack` / `fmdecay`; each TIMBRE sound starts it where its filter envelope is): FM LVL = the settled modulation, each note's FM envelope lifts it (BASS / PLUCK 0.5 -> 5x, PAD / LEAD up to 4x, `fmEnvGain`). INTENSITY never moves FM LVL / FEEDBACK on the synths: the sound design runs TIMBRE > INT > FM > filter. ARP is a track setting on any track (`engine/arp.ts`, `ChannelState.arp`): the ARP key = on / off for the selected track, FUNC + ARP = its knobs (FUNC lets go, held or latched; the view has no FUNC layer; ARP again = back, never on / off; MODE, OFF by default, so it stays silent until a MODE is picked; RATE; OCT); while a note is held its chord tones (CHORD / NOTES; drums: the note over OCT octaves) play in turn. DRIVE is level-compensated per type (`driveComp.ts`).
- PRESET loads factory sounds and USER patches saved by older versions (new USER patches can't be saved).

### Mixer, FX, LFO, master
- Per track: VOLUME, PAN, SEND LVL, MID CUT (`fx/TrackCut.ts`, centre = the sound's MID FREQ), ACC/GHOST, TRIM (synths) / RING (drums), mute / solo. MUTE stops the sequencer starting new notes on the track (`Engine.muted`): what is sounding plays out (tails into the FX too), an unmuted track comes back on its next note, never mid-tie; keys played live still sound. SOLO mutes the others the same way.
- Three FX buses (`fx/buses.ts` defines them, `fx/FxBus.ts` runs one, `fx/units.ts` holds the effects): four units of two knob modules each, no FUNC layer. An effect unit (not COMP / TONE / FILTER) = VOLUME (return level) over TYPE, then its two controls (MOD RATE / DEPTH, DELAY RATE (tempo-synced) / FDBK, VERB SIZE / LENGTH, DIST DRIVE / TONE). A TYPE change fades over 15 ms; a unit at VOLUME 0 is skipped.
- FX 1 = drums (an insert: the drums stay in the mix through COMP (RATIO / THRESH, ATTACK / RELEASE, 1:1 = off), plus MOD (FLANGER, PHASER), DELAY (TAPE, SWEEP, REVERSE) returning alongside; then FILTER on the drums and both returns: module 7 FILTER (one knob, `djCutoff`: low-pass left, high-pass right, OFF in the centre, skipped) / RESO, module 8 ENV (each hit lifts / lowers the cutoff, up to 8 octaves) / ENV REL). Transparent by default.
- FX 2 = PAD send: MOD (CHORUS, ENSEMBLE, PHASER), DELAY (STEREO, PING-PONG, TAPE), VERB (HALL, PLATE, SHIMMER), TONE (LOW CUT / HI CUT on the returns, PUMP / PUMP REL: KICK hits duck the returns).
- FX 3 = LEAD send: DIST (TUBE, FUZZ, BIT), DELAY (PING-PONG, DUB TAPE, SLAPBACK), VERB (ROOM, PLATE, SPRING), TONE (LOW CUT / HI CUT, DUCK / DUCK REL: the bus input ducks its own echoes).
- Each track feeds at most one send (by SEND LVL); FX 1 is separate. A new project routes KICK / SNARE / HAT / PERC to FX 1, PAD to FX 2, LEAD to FX 3; BASS and PLUCK have their own effects.
- One shared tempo-synced LFO (bus button 4): rate, shape + MORPH, phase, smooth, fade in, retrig, vol / pitch / filter / pan / send / FM mod, spread; tracks join it like a send.
- No track is on the LFO in a new project. Master: MASTER (x sqrt2 pan-law make-up) -> look-ahead limiter (`fx/Limiter.ts`, -1 dBFS). No master colouring.

### Saving
- Startup = blank slate (`createDefaultProject`, no project open). The working project is mirrored to the artifact db `projects/current` (`storage/cloud.ts`). `startProject.json` is for tests only.
- Projects (`storage/projects.ts`, `ProjectStore`): 64 slots (4 banks x 16); each has a saved copy and a working copy. Stopped only: SAVE PROJECT = save menu (name entry with knobs 1-4 = A-Z / a-z / 0-9 / symbols, ◀ ▶ cursor, BAR + ◀ ▶ bank, tap a slot; another project's slot = tap twice; the strip shows the slots alike in every mode, never as keys); FUNC + SAVE PROJECT = load (CLEAR + slot twice = delete; an empty slot = a new project: the default one, nothing open, the open project's edits kept in its slot; a never-saved changed project needs a second tap; SAVE then opens on that slot's bank, `App.newProject`).
- Cloud slots (`storage/slotSync.ts`, claude.ai only): the slots mirror to the db collection `slots`; `planSync` merges on start and when SAVE/LOAD opens.
- The saved state: each pattern's `savedNotes` / `savedPatch`, and `App.saved` for the rest (one copy without patterns: the open slot's saved project, else as the session / new project began). The working copy's automatic save warns `STORAGE FULL: NOT KEPT` when storage refuses it.
- There is no pattern SAVE: SAVE PROJECT saves every pattern and patch (`lockProject`); edits since show * on the pattern keys / screen. RESET: patches back to saved (gliding to the next bar line while playing), mix / FX / LFO to the saved project, live knobs centred; a second tap within 3 s = notes too; held channel buttons = those tracks (with the FX / LFO knobs their LIVE 1-4 move, e.g. KICK's FX1:MOD), held FX 1-3 / LFO = that bus / the LFO (its view is left as before the press; any mode): HOLD + RESET KEEP HELD keeps them out of it, RESET HELD resets only them (SWING then stays).
- File format: `engine/projectFile.ts` (compact; forgiving: missing / out-of-range values take defaults, notes are never lost). Format v59 (`PROJECT_VERSION`; v59 added SCALE's `root` / `chromatic` (missing = A minor; no migration, so older projects' keys are A minor too); v58 load (`leadV58`, also USER patches): LEAD's sound rebuilt from the new engine's sounds at its TIMBRE / INT under its stored trims (none stored: none kept), notes, mix, ATTACK / RELEASE kept; v57 load (`rollRateV57`, also USER patches): ROLL RATE became a note value, every older save's drums roll at 1/16; v55 added a track's ARP `arp` (missing = off) and steps with locks but no note (`o: 1`); lock keys may be any knob's (no migration: older locks are sound params by bare id); v54 added the HOLD + PATTERN setting `settings.holdPattern` (missing = DEFAULT; no migration); v53 added the song's automation `song.a` (missing = none; no migration); v52 added the project's own GLOBAL settings `settings` (missing = DEFAULT; no migration); v51 load (`liveV51`): every track's live knobs back to its type's defaults as they are now (asked for once, so every older project gets PLUCK LIVE 2 = SPACE etc.; custom live knobs in older saves are reset); v50 added a track's RING `ringLength` (missing = x1, as designed; no migration); v49 load (`typeGainV49`): the type gains were re-set with the gated measure (HAT 4.359 -> 1.783 ...), so each saved VOLUME is scaled by old / new gain; a VOLUME that would pass 1 (on a track with notes) brings every track down and MASTER up (as far as 1), a track without notes is just capped; the per-sound level fixes are not undone; v48: FX 1's VERB became FILTER, an old FX 1 VERB setting is dropped (no migration); v42 added a PAD step's note lengths, stored `cg`); it reads v40 on exactly (`OLDEST_EXACT`; v41 load: FM ATK / DEC from FLT ATK / DEC incl. trims and locks (`fmEnvV41`), FX 2 / FX 3 routing swapped, old FX settings replaced by the bus defaults; v43 load (`drumsV43`, also USER patches): a KICK's BD DEC becomes a trim (TIMBRE now sets it, 0.5 s) and its other TIMBRE / INT values are rebuilt under its trims; SWEEP trims rescaled to the 0-120 st range; ### Engine safety and performance
- A non-finite engine output mutes the block and starts a fresh engine (ENGINE RESTARTED; main resends the project). The fast tables in `math.ts` (`sinTurn`, `exp2`) guard their last entry: an input a hair below a whole number (t = -1e-17) rounds the fraction to exactly 1 and used to read one past the table (NaN; a dying LEAD BEND hit it). `LOCK_SLOTS` (48) holds every type's sound parameters (PAD's 34 spilled into the next track's at 32). The worklet file is re-fetched with `cache: 'reload'`.
- STOP always gets through: besides the message it sets the worklet's `stop` AudioParam (an overloaded audio thread can hold messages back while it still renders); transport messages carry the UI's PLAY / STOP count (`gen`) and older ones are dropped.
- Clicks avoided: hit tone glides 3 ms, held-voice velocity follows over 4 ms, drum retrigger and REST fades 3 ms (`CUT_FADE`); a MONO synth (BASS) note while the last one still sounds (held or releasing, not a slide) starts fresh on a second voice while the old one fades over `CUT_FADE` (`Synth.monoVoice`; retriggering in place made its filter / FM envelopes jump while heard).
- CPU: FxBus skips units at VOLUME 0 and a send goes idle after 5 s of silence; PLUCK's onboard delay + room and the drums' AIR idle the same way (`IdleGate`); a track with silent output skips its hit-tone filter and mixing, and with its levels at rest mixes with per-block gains (bit-identical output); the reverbs use whole-sample comb delays while SIZE is at rest; PixelScreen redraws only changed frames. Synth voices render in blocks in two stages (`Synth.renderVoices`: phases, oscillators per algorithm with SHAPE's waves a block at a time (`waves`; only the self-feeding carrier 1 of algos 1 / 2 goes sample by sample), UNISON, then envelopes / filter / level), so V8 inlines the wave code; bit-identical to the old per-sample loop. The reverbs (FX VERB with SIZE at rest and no SHIMMER, `VerbFx.renderBlock`; the PLUCK room, `Reverb`) run each diffuser, comb and allpass over a block in turn (bit-identical); COMP converts dB to gain only when it changed; a drum's pitch sweep stops calling `pow` once it has died to exactly 1 (`sweepFlat`). What is left in the drums and FX is the DSP itself (per-sample `sin` / `tanh` / `pow`, comb memory). Those per-sample calls go through `instruments/math.ts` (`sinTurn`, `cosTurn`, `sinRad`, `tanh`, `exp2`, `pow10`): FAST table versions with linear interpolation (-124 dB or better against `Math.*`; a test checks), the app's maths since October 2026: offline 12-41 % less engine time on the saved projects / stress groove, 34-47 % in Chromium; against exact the output differs by -116 to -128 dB (median), the most on CRUSH (a value tips into the next step, -72 dB) and strong FM FEEDBACK (small differences grow, -77 dB): the same sound, not the same samples (judged by ear in the lab: no difference). `mathExact.ts` keeps the exact ones (`Math.*`) for the lab's B engine and the test. Any further engine refactor is checked bit-identical against the app's own (fast) output. Engine cost on a fast desktop core: the saved projects 3.5-10.5 % of real time; allocation while playing, measured in October 2026 on the bundled engine (as the browser runs it; Node 22, warmed, heap growth with no GC during the run): 0.14-0.37 MB/s on the saved projects, groove and stress source, i.e. one small GC every minute or so: nothing per sample (each module alone stays under 80 kB/s), the rest is per-block work spread thinly (about half in the drums' render). The earlier ~1.6 MB/s figure came from the Vitest-transformed code, and V8's sampling heap profiler inflates allocation 15-60x (it shows where numbers would be boxed if optimisation failed), so neither is a guide; measure on a bundled build. The panel redraws at the display rate for 1.5 s after any touch, else 30 fps while playing and 15 fps when idle (`main.ts` frame loop; input is handled at once). The screen footer cycles OUT (latency), DSP (the audio thread's load), UI ms per frame and UI fps every 3 s; DSP from 80 % stays up, flagged. Measured with the CPU slowed 4x: drawing costs 0.2-0.8 ms per frame; main thread busy stopped 5 % -> 2.5 % idle, playing ~13 % -> ~12 %.
