# GrooveAccess (repo: groovebox)

Web-first groovebox (techno, DnB, dub, jungle). Full spec: `groovebox-brief.md` (read it first).

## Rules
- Work milestone by milestone (section 12 of the brief); keep the build green; commit after each working step.
- `src/engine`, `src/instruments`, `src/fx` must stay free of DOM and Web Audio code.
- Audio thread: no allocation per block, no console.log, no blocking.
- Keep sound design basic at first; clean interfaces for refining later.
- Must work in desktop Chrome/Edge and Silk on a Fire tablet (touch, multi-touch).
- `main` is the source of truth: every session starts from it. After committing a working step, push it to the session branch and also to `main` (`git push origin HEAD:main`; if `main` moved, merge `origin/main` first, never force-push), so the next session starts with every change.

## Platform plan (agreed; not started)
Goal: the Android / Fire APK becomes the main version; the web build stays as the dev and preview build. Order:
1. **Sound first.** Finish the sound design in the TypeScript engine (current milestones). No port while the sound still changes: every tweak would have to be made twice.
2. **Capacitor shell (can come earlier).** Wrap `dist/` in a Capacitor Android app (served from `https://localhost` so AudioWorklet works; media playback without a gesture, keep screen on, immersive, landscape); a native `ProjectStore` (Capacitor Filesystem / Preferences) instead of localStorage; sideload on the Fire or publish to the Amazon Appstore (no Google Play Services). Measure the Fire with OboeTester (round-trip latency, MMAP support) to see what a native engine would gain.
3. **Native engine.** Port `src/engine`, `src/instruments`, `src/fx` to Rust (a thin C++ Oboe shim for the audio callback: AAudio, LowLatency + Exclusive, buffer = 1-2 bursts, sustained performance mode), behind the existing message protocol, so the UI barely changes. Keep `double` for filter / oscillator state, the same random generators, flush denormals to zero. Port module by module and **null-test** each against the TypeScript engine (render the same project offline, subtract, expect around -100 dB or lower).
4. **After the port:** the APK is the product (releases, latency work, Android-only features behind small interfaces like `ProjectStore`). The same Rust engine compiles to WASM for the web build (same UI, same sound): used for development, tests and the Artifact preview, never maintained or tuned separately. Then update this file's targets to "Android / Fire APK first; web = dev and preview build".

## Keeping these docs right
- This file describes the app **as it is now**. When behaviour changes, edit the section it belongs to (replace the old description, don't append a dated note), and add a one-line entry to `docs/HISTORY.md`.
- Save format changes: bump `PROJECT_VERSION` (`engine/project.ts`), add the load migration in `engine/projectFile.ts` (named after the version it upgrades from, e.g. `...V40`, guarded by the stored `version`), and record it in `docs/HISTORY.md`. Old migrations can be retired by raising `OLDEST_EXACT` (as in October 2026, see HISTORY).
- `ARCHITECTURE.md` = code structure, message protocol, data model. Keep its protocol table in step with `engine/protocol.ts`.
- Never trust a comment over the code: if they disagree, fix the comment in the same commit.

### Panel
- Grid (design 1200 x 760, every box on a whole pixel at 1:1): content 1152 px (22 px side padding); 8 knob modules of 144 px; beside the screen a 592 px column: modes 140 px, each over a pair of the 66 px FX / PATTERN keys (FX group and PATTERN group 288 px, 16 px apart), CANCEL / SAVE/LOAD / RESET and page buttons 92 px over the FX group, TEMPO / MASTER box over the PATTERN group; strip steps and function keys 55 px, 6 px gaps, 16 px between groups of four; PLAY column 136 px. Button corners 4 px.
- Lettering: Sarpanch Medium / Bold, sizes 2 px up from the first Sarpanch layout (`src/fonts`, SIL OFL, inlined into the build by `vite.config.ts` `assetsInlineLimit`), never faked bold. The pixel screen keeps its own pixel font.
- Start-up: the panel opens zoomed in on its pixel screen (`Panel.setZoom`), showing the title card in the pixel font (`views.drawTitleView`: GrooveAccess / A Garibaldi Production / TAP TO START, LOADING, READY); a see-through overlay (`#title`) keeps the controls out of reach. Once the engine's first status report arrives (audio needs the first tap), it holds 0.7 s and zooms out to the whole panel over 1.2 s (`main.ts` `titleFrame`; at once with reduced motion).
- Beside the screen: modes RECORD / PLAY / DESIGN, then MENU (label MENU / SONG while in SONG); CANCEL (Escape), SAVE/LOAD PROJECT, RESET over the page buttons (3), TEMPO / MASTER beside them; at the bottom FX 1 / 2 / 3 / LFO and PAT A-D as square keys, FX / PATTERN printed above.
- 16 knobs in 8 track modules (k1-k8 top row, k9-k16 bottom; module n = k(n) over k(n+8)); between a module's knobs its track's M (mute), channel button (select on release) and S (solo, not saved; Alt+1-8); knob names run up the left side (rotated). Absolute 0-127 over 270°; a drag moves faster the quicker it goes (slow = 400 px for the full range at KNOB SPEED NORMAL (SLOW 600, FAST 250), up to 6x with KNOB ACCEL on, `Knob.ts` ACCEL_*; Shift = fine); `encoder` events (mouse wheel, hardware) are relative.
- Function row: 16 keys, each straight above its strip step: RING, SLIDE, ACCENT, GHOST | STEPS, BAR, CLEAR (hold), COPY (hold) | TIME (pattern speed), two blank keys (not wired), REST | OCT ▼, OCT ▲, ◀, ▶. Then the step LEDs and the 16-step strip; a divider after every four steps runs from the function row down through the strip (`.strip-divider`), the last one under the groove between modules 7 and 8. Right of it FUNC (Z; hold = second knob layer, tap = latch; level with the function keys + LEDs) over PLAY (Space; level with the strip). Master knobs TEMPO (whole BPM only: knob and encoder steps of 1, saves load rounded, so a DAW gets the same tempo) and MASTER.
- Keyboard: 1-8 channels (Shift = mute, Alt = solo), QWERTYUI / ASDFGHJK = strip.
- Touch: `main.ts` cancels touch defaults; the panel runs on pointer events; everything lets go on `lostpointercapture`, blur and hidden (`Panel.releaseAll`). Portrait screens rotate the panel (`orientation.ts`).

### Modes
- **MENU** (the top row's fourth button, `App.menu`, `App.menuLines`, `views.drawMenuView`): pages of lines, the path in the title. Settings change on screen first (shown with ? and a red LED, per page: `MainMenu.stack[].pending`); PLAY saves the page's changes and goes back a page, CANCEL goes back without saving. Top: MODE (JAM / SONG; JAM = back to the mode SONG was entered from), PROJECT SETTINGS > TRACKS (TRACK 1-8: a type or OFF; saving one runs `App.setTrackType`: notes kept, every pattern (and its saved patch) gets the type's starting sound (`defaultProject.trackDefaults`), locks dropped, live knobs and CHORD to the type's defaults, mix and routing kept). GLOBAL SETTINGS > TOUCH SETTINGS (kept on the device, not in projects: `storage/settings.ts`, localStorage `groovebox.device`): KNOB SPEED (SLOW / NORMAL / FAST), KNOB ACCEL (ON / OFF), TOUCH DELAY (0-50 ms), HOLD TIME (SHORT / NORMAL / LONG: how long FUNC may be down and still count as a tap that latches, 250 / 350 / 500 ms), KEEP SCREEN ON (PLAYING / ALWAYS: the wake lock, `main.ts`). Planned: PATTERN SWITCH, SCALE / ROOT under PROJECT SETTINGS; COUNT-IN, METRONOME, CLICK LEVEL, MIDI SETTINGS, ABOUT under GLOBAL SETTINGS. Keys: ▼ / ▲ (the OCT keys) move, ◀ ▶ (or knob 1) change a setting, ▶ opens a page, a strip key goes to its line (and opens a page), PLAY = save + back, CANCEL (or ◀ on a page line) = back without saving, MENU closes without saving; a mode button closes it and goes there. While MENU is open PLAY is not the transport.
- **CANCEL** (`App.cancel`): backs out of what is open, innermost first: the SAVE / LOAD screen, MENU, an FX / LFO view, RECORD flag placing, STEPS mode, REST armed; nothing open = nothing. FUNC + CANCEL = UNDO (not built yet: says UNDO: NOT YET).
- **RECORD.** Stopped = step entry, playing = live recording (notes, releases and knob locks land where they were heard: `setListenLatency` = output latency + TOUCH DELAY, 15 ms by default).
  - Drum lanes (KICK, SNARE, HAT): the strip toggles steps; drag (or press the next step while one is held) to paint a stroke; the first step decides add / erase / flags / rests.
  - Keyboard tracks (PERC and the synths): note at the cursor, then the cursor advances; hold a key + ▶ / ◀ = tie it longer / shorter (a tie clears notes and REST markers on the steps it covers); REST = rest marker. A key pressed while another is held goes on the next step, except on the polyphonic tracks PAD and PLUCK (`registry.playsChords`) with CHORD OFF (`App.stepChords`), where it joins the same step as a chord (up to 6 notes). With a CHORD on, PAD / PLUCK play one root at a time like BASS / LEAD (`App.isMono`): held keys slide chord to chord (live and recorded), step entry goes on the next step. PAD / PLUCK: every note has its own length (`Step.extraGate`; ▶ / ◀ tie only the note(s) being entered and never clear other steps), so notes overlap freely; a key on a step that already has notes joins it as a note of its own, the same key again takes it out (`App.addChordNote`). At most 6 notes sound at any step: adding (or tying) a seventh replaces the one that started earliest, or among notes that started together the nearest in pitch (`App.makeRoom`). BASS / LEAD (and chord-mode PAD / PLUCK: one note at a time; held keys slide) replace, and their ties clear the steps they cover. PAD / PLUCK strip in step entry: the yellow ring = only the note(s) being entered and the step LEDs show only that note's steps (as over an empty step); the other notes sounding at that step (on it or tied over) light dim teal (`soundingAt`). While playing, every PAD / PLUCK note sounding at the playhead lights dim teal; keys held down show bright teal. Live recording on PAD / PLUCK: keys pressed while one is held join its step if they land on it or come within 80 ms of it (`CHORD_WINDOW`, `Engine.recordChordNote`), each with its own length from its own release (`releaseChordNote`).
  - RING / SLIDE / ACCENT / GHOST (one at a time): tap = placing mode (the strip shows steps; tap a note to toggle the flag; on tied-over steps the flag goes on the note), tap again = back. Drum lanes: the armed flag goes onto painted steps. ACCENT / GHOST never remove a drum note.
- **PLAY.** The strip is a keyboard for every track. Patterns switch at the loop end, and their patches glide in. RING / SLIDE / ACCENT / GHOST = every note on the selected track plays that way (`setForce`, `App.forcing`; not stored; the same in DESIGN and kept between PLAY and DESIGN; off when going to RECORD or SONG). Pages: SOUND (live knobs, always opens here) / MIX.
- **DESIGN.** Pages: SOUND (the selected track's sound page; FUNC = its FUNC layer), MIX (global: VOLUME / PAN per track; FUNC = SEND LVL / MID CUT), PROJECT (global: TEMPO, SWING, MASTER, TIME SIG; ACC/GHOST per track; FUNC = TRIM per synth track). RING / SLIDE / ACCENT / GHOST work as in PLAY (every note plays that way). A channel tap opens its SOUND page. OCT ▼ / ▲ on a synth = the sound's OCTAVE (-4 ... +4, part of the patch); otherwise the keyboard octave.
- **SONG** (MENU > SONG MODE). Tracker grid: rows of bars + pattern A-D / OFF per track, switched at bar lines, looping. Knobs: top = each track's pattern in the cursor row, bottom 1 = BARS. ◀ ▶ = column, ROW ▼ / ▲ (the OCT keys) = next / previous row, INSERT / DELETE (the RING / ACCENT buttons), strip = jump to a row (at the next bar while playing), BAR = next page of rows. PLAY here plays the song from the cursor row (FUNC + PLAY = from row 1).
- **In every mode but SONG:** FX 1-3 / LFO tap = that bus's knobs on screen (again, or a page button, = back); FUNC + FX = selected track on / off that bus; with a bus open, FUNC + channel = that track on / off it.

### Patterns and steps
- 8 tracks x 4 patterns A-D, 1-64 steps (STEPS held + ◀ / ▶ = a bar shorter / longer). BAR tap = next bar on the strip, BAR + ◀ / ▶ = previous / next. While playing, PLAY, DESIGN and live recording (placing RING / SLIDE / ACCENT / GHOST included) follow the playhead (`App.followsPlayhead`; BAR is off there).
- PLAY starts from the bar the strip shows for the selected track (BAR picks it, stopped, in every mode): every track starts where it would be had all played from the top until then (`Engine.startAt`; a 2-bar HAT from bar 4 plays its bar 2; notes started earlier don't sound). STOP keeps each track's bar (`App.keepBars`), so PLAY carries on from there. FUNC + PLAY = from the top (stopping: back to the top for the next PLAY) and lets go of FUNC (held or latched).
- A-D = every track's pattern; hold channels + A-D = only those (several at once); FUNC + A-D = the selected track. Playing, a switch always waits for the track's loop end (any mode); stopped = at once.
- Speed per pattern: normal / double / half / triplet (the TIME key cycles them, its label shows the speed; screen X2 / /2 / T). One master 16th clock; `Engine.stepChannel` runs each track's own steps.
- TIME SIG (`project.meter`, `METERS`): each 16-step bar has four groups and plays the first n of each; dark steps take no time; changes at the next bar line. STEPS tap = STEPS mode: strip taps flip a step on / off (`Step.flip`).
- Step flags: SLIDE (303-style: held through to the next note and glides into it; legato playing on BASS / LEAD slides too), RING (held until the next hit or REST; a REST under the note's own tie doesn't end it, `Engine.tieLeft`; drums ring with long decay), ACCENT / GHOST (velocity 1 / 0.45, normal 0.8; ACC/GHOST per track scales the distance), REST, locks (per-step sound params, written by live recording), PAD / PLUCK chord notes (`Step.extra`, each with its own length `Step.extraGate`; the engine holds their notes each by its own length, `holdStart` / `stepHolds`, so a later note no longer cuts an earlier one; RING / SLIDE steps keep the one-note gate; a CHORD other than OFF plays only the step's lowest note, as its root; a SLIDE glides the chord voice by voice: root to root, 3rd to 3rd ..., at the sound's SLIDE time).
- Drum ROLL (the SLIDE flag on drums): consecutive ROLL steps roll as one run at the sound's ROLL RATE (1:1 ... 1:8 hits per step), velocity ramping from the first step's dynamic to the last's; lone ROLL steps don't roll.
- TRIM (per track): the last step of a sequenced note is held this long (0.125-2 steps).
- CLEAR held + step = clear it; + channel = clear that track's pattern; + A-D = clear that pattern of the selected track (the current one too). COPY held + channel = this pattern (notes + patch) to the same slot on that track (same type only); + A-D = to that pattern of this track.
- Each pattern has its own patch (`Pattern.patch`; the pattern being edited keeps its patch in the channel's `sounds` / `trims` / `presets`: always use `patchOf` / `setPatchOf` / `editPattern`).

### Sounds
- Track types: 1 KICK, 2 SNARE, 3 HAT, 4 PERC (pitched toms / percussion), 5 BASS, 6 PAD, 7 LEAD, 8 PLUCK (default layout; any track can take any type).
- **Layers**, bottom to top: TIMBRE / INTENSITY macros (`macros.ts`: TIMBRE blends five designed sounds per type; INTENSITY = modulation amount, below 50 % towards a dull floor, above excited; the KICK's sounds instead each have their own INT 0 (soft, slow thump) and INT 100 (extreme) versions, `Anchor.soft` / `hard`; PERC COWBELL has its own soft end so INT 0 keeps its metal) < SOUND page knobs (stored as **trims** on top of the macros, `trims.ts`, so turning TIMBRE keeps them) < LIVE knobs (relative, in the engine via `setOffset`).
- Five TIMBRE sounds per type: KICK 808 BOOM / VINTAGE / PUNCH / TECHNO / PSY DOOF; SNARE RIMSHOT / PICCOLO / TIGHT / BREAK / INDUSTRIAL; HAT RIDE / HAT / SPLASH / CRASH / CHINA; PERC LOW TOM / CONGA / COWBELL / TIMBALE / CLAVE (skins, metal, wood); BASS SINE SUB / GROWL / ACID / SOLID / FM 2:3; PAD WARM / STRINGS / TINE / GLASS / ETHEREAL; LEAD ODD 2:3 / ORGAN / SAW 1:1 / OCT 1:2 / FIFTH 3:2; PLUCK STEEL / GLASS PLUCK / SAW PLUCK / SQUARE PLUCK / RAGE DONK.
- Loudness: every TIMBRE sound on every type plays equally loud at the default VOLUME, at INT 0, 50 and 100 (within 1 dB; tests; measured 0.43 dB apart). The measure is GATED (`tools/lab/loudness.ts` `gatedLoudness`): one hit / a half-second note, K-weighted, averaged over the samples whose 10 ms loudness is within 20 dB of the loudest moment, so short sounds (a hat passes the gate for ~30 ms) and long ones are compared on how loud they are while they sound, not diluted by their tail. Per-sound `ogain` evens a type's sounds (its `soft` / `hard` ogain evens INT 0 / 100; an end with only `ogain` changes nothing else); `InstrumentEntry.gain` sets the type, all against the KICK.
- SOUND page layouts live in `registry.ts` (`drumPage`, `synthPage`, FUNC layers) — read them there, not here. Synths follow the sound chain: 1 TIMBRE / INT, 2 amp envelope, 3 FM ATK / FM DEC, 4 FM LVL / RESO, 5 FLT ATK / FLT DEC, 6 FLT ENV / CUTOFF, 7 DRIVE / CRUSH (PAD: DRIVE / UNISON, no CRUSH), 8 BASS SLIDE / SUB, PAD CHORD / SLIDE (DETUNE on its FUNC), LEAD SLIDE / DETUNE, PLUCK DLY TIME / DLY FDBK. Every FUNC layer also holds PRESET (module 1 top), MID FREQ (4 bottom), LIVE 1 / 2 (5), LIVE 3 / 4 (6). Drums have no other FUNC knobs, except KICK / SNARE: SWEEP / SWP TIME on FUNC 2. KICK page: 5 CLK RESO / CLK NOISE, 6 AIR LVL / AIR SIZE; SNARE: 5 MTL TONE / MTL NOISE, 6 AIR LVL / AIR SIZE; 8 ROLL RATE / BALANCE on every drum.
- PAD / LEAD: module 2's ATTACK / RELEASE and FUNC DECAY / SUSTAIN move both oscillators, and FM LVL moves FM LVL2 too (`registry.linkedParams`, applied in `App.paramTarget`, in live knobs via `liveTargets`, on load for saves without them); OSC 2's own ATTACK / RELEASE are FUNC module 3, FM LVL2 (the second stack's modulation: PAD stack 2, LEAD carriers 2 / 3) FUNC module 4 top. SLIDE (time): PAD module 8 bottom, PLUCK FUNC module 3 top.
- Live knobs: two per track (+ two with FUNC), defaults in `INSTRUMENTS[kind].live` / `liveFunc` (KICK / SNARE / HAT top knob = FX1:MOD / FX1:DELAY / FX1:FILTER); macros in `LIVE_MACROS`. LIVE 1-4 can take the type's macros, every knob on its SOUND page (both layers), the mixer, every FX effect's VOLUME and FX 1's FILTER (`FX_LIVE`, ids `fx<n>:<param>`, named `FX<n>:...`; they move the bus knob itself) and the LFO. Relative: centred = the sound as set, ±60 % of the range with a taper; CUTOFF / RESO / CHORD / NOTES, choice knobs (ROLL RATE, DLY TIME), mixer, FX and LFO ids are absolute. RESET centres them.
- **Drums** (`Drum.ts`): layers body (tone + sweep), click, metal (808-style bank / ring-mod / FM + noise; HAT only: BELL `m_bell`, eight sine partials at a cymbal bell's ratios past the metal's high-pass, and RATTLE `h_rattle`, four jingle re-hits gating the metal's start; TIMBRE's (only RIDE has them: a high ride, about 1.47 kHz, after the Boss DR-3's ride bell; INT leaves its pitch), no knob) -> DRIVE -> CRUSH (fractional-rate) -> OUT GAIN -> AIR (KICK, SNARE: a small room on the track, `Drum.post`, its tail through a fixed EQ per type, `DrumVoice.air`: KICK high-pass 350 Hz x2 / low-pass 2.5 kHz, SNARE 400 Hz x2 / 6 kHz; AIR LVL (square law, 0 = off and idle) / AIR SIZE). No filter per drum (FX 1's FILTER is the kit's). BALANCE between the elements; RING = decays x3 + a fixed 0.6 s extension. A retrigger fades the old hit over 3 ms.
- **Synths** (`Synth.ts`, up to 6 voices): BASS mono (one envelope for both oscillators, own filter envelope, sub, FM ratio ladder 1:2 / 2:3 / 3:2 root-locked, SIDECHAIN DUCK from KICK hits, FUNC under module 7); PAD polyphonic, algorithm 2 (two FM stacks, stack 2 mixed in by CARRIERS (no knob: 0.85 on every TIMBRE sound, INTENSITY fades it out below the middle and up to 1 in the top quarter; INTENSITY leaves FM LVL / FEEDBACK alone); chords via CHORD / NOTES or on-step notes); LEAD 3 voices, algorithm 1 (DX7-style: 3 carriers + 1 feedback modulator; INTENSITY sets CARRIERS: 0 = carrier 1 alone, full in the top quarter); PLUCK polyphonic with onboard delay + room (CHORD / DETUNE and DLY MIX / VERB on FUNC). Every synth has an FM envelope of its own (FM ATK / FM DEC, `fmattack` / `fmdecay`; each TIMBRE sound starts it where its filter envelope is): FM LVL = the settled modulation, each note's FM envelope lifts it (BASS / PLUCK 0.5 -> 5x, PAD / LEAD up to 4x, `fmEnvGain`). INTENSITY never moves FM LVL / FEEDBACK on the synths: the sound design runs TIMBRE > INT > FM > filter. The PLUCK's ARP has no controls for now (the engine still plays `arp` / `arprate` / `arpoct` if a type lists them again). DRIVE is level-compensated per type (`driveComp.ts`).
- PRESET loads factory sounds and USER patches saved by older versions (new USER patches can't be saved).

### Mixer, FX, LFO, master
- Per track: VOLUME, PAN, SEND LVL, MID CUT (`fx/TrackCut.ts`, centre = the sound's MID FREQ), ACC/GHOST, TRIM, mute / solo. MUTE stops the sequencer starting new notes on the track (`Engine.muted`): what is sounding plays out (tails into the FX too), an unmuted track comes back on its next note, never mid-tie; keys played live still sound. SOLO mutes the others the same way.
- Three FX buses (`fx/buses.ts` defines them, `fx/FxBus.ts` runs one, `fx/units.ts` holds the effects): four units of two knob modules each, no FUNC layer. An effect unit (not COMP / TONE / FILTER) = VOLUME (return level) over TYPE, then its two controls (MOD RATE / DEPTH, DELAY RATE (tempo-synced) / FDBK, VERB SIZE / LENGTH, DIST DRIVE / TONE). A TYPE change fades over 15 ms; a unit at VOLUME 0 is skipped.
- FX 1 = drums (an insert: the drums stay in the mix through COMP (RATIO / THRESH, ATTACK / RELEASE, 1:1 = off), plus MOD (FLANGER, PHASER), DELAY (TAPE, SWEEP, REVERSE) returning alongside; then FILTER on the drums and both returns: module 7 FILTER (one knob, `djCutoff`: low-pass left, high-pass right, OFF in the centre, skipped) / RESO, module 8 ENV (each hit lifts / lowers the cutoff, up to 8 octaves) / ENV REL). Transparent by default.
- FX 2 = PAD send: MOD (CHORUS, ENSEMBLE, PHASER), DELAY (STEREO, PING-PONG, TAPE), VERB (HALL, PLATE, SHIMMER), TONE (LOW CUT / HI CUT on the returns, PUMP / PUMP REL: KICK hits duck the returns).
- FX 3 = LEAD send: DIST (TUBE, FUZZ, BIT), DELAY (PING-PONG, DUB TAPE, SLAPBACK), VERB (ROOM, PLATE, SPRING), TONE (LOW CUT / HI CUT, DUCK / DUCK REL: the bus input ducks its own echoes).
- Each track feeds at most one send (by SEND LVL); FX 1 is separate. A new project routes KICK / SNARE / HAT / PERC to FX 1, PAD to FX 2, LEAD to FX 3; BASS and PLUCK have their own effects.
- One shared tempo-synced LFO (bus button 4): rate, shape + MORPH, phase, smooth, fade in, retrig, vol / pitch / filter / pan / send / FM mod, spread; tracks join it like a send.
- No track is on the LFO in a new project. Master: MASTER (x sqrt2 pan-law make-up) -> look-ahead limiter (`fx/Limiter.ts`, -1 dBFS). No master colouring.

### Saving
- Startup = blank slate (`createDefaultProject`, no project open). The working project is mirrored to the artifact db `projects/current` (`storage/cloud.ts`). `startProject.json` is for tests only.
- Projects (`storage/projects.ts`, `ProjectStore`): 64 slots (4 banks x 16); each has a saved copy and a working copy. Stopped only: SAVE PROJECT = save menu (name entry with knobs 1-4 = A-Z / a-z / 0-9 / symbols, ◀ ▶ cursor, BAR + ◀ ▶ bank, tap a slot; another project's slot = tap twice; the strip shows the slots alike in every mode, never as keys); FUNC + SAVE PROJECT = load (CLEAR + slot twice = delete; an empty slot = a new project: the default one, nothing open, the open project's edits kept in its slot; a never-saved changed project needs a second tap; SAVE then opens on that slot's bank, `App.newProject`).
- Cloud slots (`storage/slotSync.ts`, claude.ai only): the slots mirror to the db collection `slots`; `planSync` merges on start and when SAVE/LOAD opens.
- There is no pattern SAVE: SAVE PROJECT saves every pattern and patch (`lockProject`); edits since show * on the pattern keys / screen. RESET: patches back to saved (gliding to the next bar line while playing), mix / FX / LFO to the saved project, live knobs centred; a second tap within 3 s = notes too; hold channel buttons to keep those tracks out of it.
- File format: `engine/projectFile.ts` (compact; forgiving: missing / out-of-range values take defaults, notes are never lost). Format v49 (`PROJECT_VERSION`; v49 load (`typeGainV49`): the type gains were re-set with the gated measure (HAT 4.359 -> 1.783 ...), so each saved VOLUME is scaled by old / new gain; a VOLUME that would pass 1 (on a track with notes) brings every track down and MASTER up (as far as 1), a track without notes is just capped; the per-sound level fixes are not undone; v48: FX 1's VERB became FILTER, an old FX 1 VERB setting is dropped (no migration); v42 added a PAD step's note lengths, stored `cg`); it reads v40 on exactly (`OLDEST_EXACT`; v41 load: FM ATK / DEC from FLT ATK / DEC incl. trims and locks (`fmEnvV41`), FX 2 / FX 3 routing swapped, old FX settings replaced by the bus defaults; v43 load (`drumsV43`, also USER patches): a KICK's BD DEC becomes a trim (TIMBRE now sets it, 0.5 s) and its other TIMBRE / INT values are rebuilt under its trims; SWEEP trims rescaled to the 0-120 st range; v44 load (`hatV44`, also USER patches): a HAT's TIMBRE / INT values rebuilt from the new RIDE / sounds under its stored trims (none stored: none kept); v45 / v46 load (`percV46`, also USER patches): the same for PERC (SYN DRUM became TIMBALE; the new order), its TIMBRE, preset and TIMBRE locks moved to the same sound's new place (`percTimbreV46`); v47 load (`kickV47`, also USER patches): a KICK's trims re-taken from its stored values over the redone sounds, so it plays as saved). The migrations for v1-v39 were retired in October 2026. An older save still loads its notes and mix, its sounds as stored; LOAD then shows `OLD SAVE, SOUNDS MAY DIFFER` (`ProjectStore.isOld`).

### Engine safety and performance
- A non-finite engine output mutes the block and starts a fresh engine (ENGINE RESTARTED; main resends the project). The worklet file is re-fetched with `cache: 'reload'`.
- STOP always gets through: besides the message it sets the worklet's `stop` AudioParam (an overloaded audio thread can hold messages back while it still renders); transport messages carry the UI's PLAY / STOP count (`gen`) and older ones are dropped.
- Clicks avoided: hit tone glides 3 ms, held-voice velocity follows over 4 ms, drum retrigger fade 3 ms.
- CPU: FxBus skips units at VOLUME 0 and a send goes idle after 5 s of silence; PLUCK's onboard delay + room and the drums' AIR idle the same way (`IdleGate`); a track with silent output skips its hit-tone filter and mixing, and with its levels at rest mixes with per-block gains (bit-identical output); the reverbs use whole-sample comb delays while SIZE is at rest; PixelScreen redraws only changed frames. Synth voices render in blocks in two stages (`Synth.renderVoices`: phases, oscillators per algorithm with SHAPE's waves a block at a time (`waves`; only the self-feeding carrier 1 of algos 1 / 2 goes sample by sample), UNISON, then envelopes / filter / level), so V8 inlines the wave code; bit-identical to the old per-sample loop. The reverbs (FX VERB with SIZE at rest and no SHIMMER, `VerbFx.renderBlock`; the AIR / PLUCK room, `Reverb`) run each diffuser, comb and allpass over a block in turn (bit-identical); COMP converts dB to gain only when it changed; a drum's pitch sweep stops calling `pow` once it has died to exactly 1 (`sweepFlat`). What is left in the drums and FX is the DSP itself (per-sample `sin` / `tanh` / `pow`, comb memory). Those per-sample calls go through `instruments/math.ts` (`sinTurn`, `cosTurn`, `sinRad`, `tanh`, `exp2`, `pow10`): FAST table versions with linear interpolation (-124 dB or better against `Math.*`; a test checks), the app's maths since October 2026: offline 12-41 % less engine time on the saved projects / stress groove, 34-47 % in Chromium; against exact the output differs by -116 to -128 dB (median), the most on CRUSH (a value tips into the next step, -72 dB) and strong FM FEEDBACK (small differences grow, -77 dB): the same sound, not the same samples (judged by ear in the lab: no difference). `mathExact.ts` keeps the exact ones (`Math.*`) for the lab's B engine and the test. Any further engine refactor is checked bit-identical against the app's own (fast) output. Engine cost on a fast desktop core: the saved projects 3.5-10.5 % of real time; allocation ~1.6 MB/s (was ~4.5; mostly the FX units and AIR now: V8 boxing doubles across non-inlined calls). The panel redraws at the display rate for 1.5 s after any touch, else 30 fps while playing and 15 fps when idle (`main.ts` frame loop; input is handled at once). The screen footer cycles OUT (latency), DSP (the audio thread's load), UI ms per frame and UI fps every 3 s; DSP from 80 % stays up, flagged. Measured with the CPU slowed 4x: drawing costs 0.2-0.8 ms per frame; main thread busy stopped 5 % -> 2.5 % idle, playing ~13 % -> ~12 %.
